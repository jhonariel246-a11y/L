El punto de partida

Dónde estamos hoy y a dónde vamos

La plataforma actual es perfecta para mostrar. Aún no es apta para abrir a clientes externos ni mover dinero. Esto es lo que cambia.

Hoy · maqueta

Sirve para mostrar

  • El acceso depende de un sistema prestado, no de una cuenta propia y segura.
  • La información vive medio suelta; difícil de proteger y de crecer.
  • Se aprueba un plan en pantalla, pero no hay compra real ni factura.
  • Un solo usuario por empresa; sin roles ni respaldos probados.
Mañana · producto real

Sirve para operar y cobrar

  • Cada cliente entra con su propia cuenta corporativa segura, por invitación.
  • Toda la información ordenada, protegida y con historial.
  • Reservas, órdenes, facturas y auditoría: compra vinculante de verdad.
  • Varias personas por empresa, cada una con su rol; respaldos y alertas.
Los cimientos

Qué vamos a reforzar

No cambiamos las pantallas. Reforzamos tres cimientos sobre Supabase (datos y acceso) e infraestructura AWS.

1

Entrada segura

Cada empresa entra con su cuenta, por invitación, con roles y permisos. Nadie entra por la puerta de atrás.

2

Base sólida

Todos los datos en una base robusta y ordenada (Supabase). Cada cliente aislado: nunca ve datos de otro.

3

Escudo permanente

Protección contra ataques, respaldos automáticos y vigilancia para detectar problemas a tiempo (AWS).

La pieza que pediste

Una consola simple para dar de alta a tus clientes

Solo para tu equipo, pensada para personas que no saben nada de programación. Escriben el nombre del cliente y el sistema hace el resto.

1

Escriben el nombre

Ingresan el nombre del cliente y unos pocos datos (empresa, correo, nº de usuarios).

2

Se genera el código

Con un clic, el sistema crea al cliente y genera un código único de registro.

3

El cliente queda listo

Se comparte el código; el cliente entra y aparece en su propia cuenta, aislada.

Así se vería (borrador)
Nombre del cliente:  Cervecería del Litoral
Dominio de correo:  @cresa.com.ec
Usuarios / asientos:  5
Generar cliente → AMK-2026-CRESA-7F3Q

Por qué así (recomendación)

  • Sin tocar la base a mano — el propio programa registra por ellos.
  • Acceso solo para personal autorizado de Ad Mavericks.
  • Queda registro de quién dio de alta a quién y cuándo (auditoría).
Tranquilidad

Su información, protegida y respaldada

Cuatro garantías desde el primer día, para ustedes y para sus clientes.

Aislamiento por cliente

Cada empresa en su propio “cuarto”. Nunca puede ver ni buscar datos de otra (RLS de Supabase).

Respaldos probados

Copias automáticas y recuperación a un punto en el tiempo, verificadas periódicamente.

Escudo contra ataques

Protección WAF y control de abuso sobre la infraestructura AWS.

Datos honestos

Nunca se inventa una cifra: si un dato no está verificado, se marca “pendiente de homologación”.

Con qué se construye

El stack: Supabase + AWS

Económico, confiable y de primer nivel. Se conserva la app visual actual (Next.js / React); el cambio es de cimientos.

Supabase datos, acceso y archivos
Postgres — fuente de verdad de planes, clientes, reservas y órdenes.
RLS — aislamiento por cliente garantizado por la base.
Auth — login por invitación, roles, SSO y MFA.
Storage — archivos privados con enlaces firmados.
AWS infraestructura
Hosting — publica la web y las APIs (Amplify / ECS).
SES — correo transaccional económico y confiable.
CloudFront + WAF — rapidez global y escudo.
S3 — respaldos y almacenamiento de objetos.
